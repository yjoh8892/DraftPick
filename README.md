# DraftPick

발로란트 내전·사설 대회에서 팀장들이 선수를 지명하는 **드래프트 픽 진행 웹앱**.

진행자가 방을 만들고 5자리 코드를 알려주면, 팀장들이 각자 브라우저로 들어와 자기 차례에 선수를 지명합니다.
누가 뽑혔는지·다음이 누구 차례인지·남은 시간이 전원에게 실시간으로 똑같이 보입니다.

## 왜 Blazor Server인가

드래프트는 본질적으로 실시간 동기화 문제입니다. 팀장 A가 선수를 지명하는 순간 나머지 팀장·관전자 화면에서
그 선수가 즉시 사라져야 하고, 턴 타이머도 모두에게 같은 초로 흘러야 합니다.

- Blazor Server는 SignalR 위에서 돌아가 이 브로드캐스트가 기본으로 딸려옵니다.
- 드래프트 상태를 **서버 메모리 한 곳**에서만 관리하므로, 클라이언트를 믿어서 생기는 문제
  (순서 무시하고 지명, 이미 뽑힌 선수 중복 지명)가 원천 차단됩니다.
- 턴 타이머도 서버가 1초마다 돌리기 때문에 클라이언트 시계가 어긋나도 상관없습니다.

## 기능

- **지명 순서** — 스네이크(1→2→3 / 3→2→1)와 순차(매 라운드 동일) 중 선택
- **턴 제한시간** — 초 단위 설정, 0이면 무제한. 시간 초과 시 남은 선수 중 최상위 자동 지명(끌 수 있음)
- **역할 구분** — 진행자 / 팀장 / 관전자. 팀장은 자기 차례에만 지명 가능, 진행자는 대리 지명 가능
- **진행자 도구** — 일시정지·재개, 마지막 픽 되돌리기, 턴 넘기기
- **명단 관리** — 한 명씩 드롭다운 입력, 또는 `이름,포지션,티어` 형식으로 일괄 붙여넣기
- **발로란트 대응** — 역할군(타격대/척후대/전략가/감시자), 랭크(아이언~레디언트) 기준 정렬
- **결과 내보내기** — 팀별 로스터를 텍스트로 복사해 디스코드에 그대로 붙여넣기

## 실행

.NET 8 SDK가 필요합니다.

```bash
dotnet run
```

기본 포트로 뜹니다. 포트를 고정하려면:

```bash
dotnet run --urls "http://localhost:5199"
```

## 테스트

```bash
dotnet test
```

`DraftPick.Tests`에 96개가 있습니다. 지명 순서·권한·되돌리기·턴 타이머처럼 화면 없이
확인할 수 있는 규칙을 전부 덮습니다. `DraftRoom`을 고칠 일이 있으면 여기부터 돌려보세요.

화면 쪽(실시간 동기화, 턴 알림 소리, 접속 표시등)은 자동 테스트가 없습니다.
브라우저 창을 두 개 열어 직접 확인해야 합니다.

## 사용 흐름

1. **방 만들기** — 진행자가 홈에서 방을 만들면 5자리 코드와 진행자 링크가 생깁니다.
2. **설정** — 팀(팀장)과 선수 명단을 등록하고 지명 방식·라운드 수·턴 제한시간을 정합니다.
3. **입장** — 팀장들이 코드로 들어와 자기 팀을 고릅니다. 관전자는 보기만 합니다.
4. **지명** — 자기 차례에 선수 카드를 누릅니다.
5. **결과** — 팀별 로스터를 텍스트로 복사합니다.

역할은 URL 쿼리에 담기므로(`?host=` / `?me=` / `?role=spec`) 새로고침해도 자리가 유지됩니다.

## 구조

```
DraftPick.sln       앱과 테스트를 묶은 솔루션
Models/
  Player.cs       선수, 역할군(Positions), 랭크(Tiers)
  Team.cs         팀과 색 팔레트
  DraftRoom.cs    방 하나의 전체 상태 — 순서 계산, 타이머, 지명 규칙, 되돌리기
Services/
  DraftRoomStore.cs   살아 있는 방들을 담은 싱글턴
  DraftTicker.cs      1초마다 모든 방의 타이머를 돌리는 백그라운드 서비스
Components/
  Pages/Home.razor    방 만들기 / 코드로 참가
  Pages/Room.razor    역할 선택 후 상태에 따라 화면 전환
  Draft/RoomSetup.razor    진행자 설정 화면
  Draft/WaitingRoom.razor  팀장·관전자 대기 화면
  Draft/DraftBoard.razor   실시간 지명 보드
  Draft/DraftResult.razor  결과 및 텍스트 내보내기
DraftPick.Tests/    dotnet test 로 도는 단위 테스트
```

`DraftRoom`이 유일한 진실 원본입니다. 상태를 바꾸는 모든 경로는 락 안에서 처리하고, 끝난 뒤 `Changed`
이벤트로 알립니다. 각 Blazor 회선은 이 이벤트를 구독해 자기 화면을 다시 그립니다.

## 이렇게 정한 것들

- **역할군은 강제하지 않습니다.** 발로란트는 한 사람이 요원을 바꿔가며 여러 역할을 소화하므로,
  팀당 타격대 몇 명 같은 제한을 걸면 오히려 방해가 됩니다. 포지션은 팀장이 조합을 눈으로
  가늠하라고 붙여둔 표시일 뿐이고, 필터와 태그로만 쓰입니다.
- **자동 지명은 남은 선수 중 티어가 가장 높은 사람을 뽑습니다.** 같은 티어끼리는 명단에서
  위에 있는 쪽을 씁니다. 진행자가 명단을 일부러 배치했다면 그 뜻이 살아 있고, 그렇지 않아도
  티어가 먼저 걸러줍니다. 시간 초과는 정신없을 때 일어나는데, 그때 결과가 "정렬 버튼을
  눌렀는지"에 달려 있으면 분쟁이 됩니다.
- **중복 이름은 알려만 주고 막지 않습니다.** 동명이인일 수 있어 판단은 진행자 몫입니다.

## 알려진 제약

- 방 상태는 **서버 메모리에만** 있습니다. 서버를 재시작하면 진행 중인 드래프트가 사라집니다.
  6시간 방치된 방은 자동으로 정리됩니다.
- 팀 색 팔레트가 8색이라 9팀부터는 색이 겹칩니다(동작에는 문제없고 설정에서 바꿀 수 있음).
- 링크 복사와 턴 알림 소리는 보안 컨텍스트를 요구합니다. localhost가 아닌 곳에 올리려면
  HTTPS가 필요합니다.
- 팀장 인증이 없습니다. 팀 선택 링크(`?me=`)를 아는 사람은 그 팀으로 지명할 수 있습니다.
  아는 사람끼리 하는 내전을 전제로 한 설계입니다.

## 다른 게임에 쓰려면

`Models/Player.cs`의 `Positions.All`과 `Tiers.All` 배열만 갈아끼우면 됩니다.
설정 화면의 드롭다운, 드래프트 보드의 포지션 필터, 정렬 기준이 전부 이 배열을 따라갑니다.
